# ConvoMoor · 对话港

一个处于测试阶段的 Chrome 扩展：保留 ChatGPT 的原生导航，在旁边整理对话、定位长对话内容、记录书签笔记，并使用自己的兼容 API 进行侧聊。

**当前为 0.3.2 预览测试版，基于 Chat Shelf 0.3.1 继续维护。** ConvoMoor 是暂定名称，未完成商标检索。不是 GPT Master 或 OpenAI 的官方产品，也未获得其背书。开发中参考过 GPT Master 的界面和安装产物；具体过程见 [开发来源](ORIGIN.md)。独立编写目标、开源协议和更名均不构成不侵权保证。

## 0.3.2 更新

- **API 设置**：打开页面自动读取已保存的地址、模型和 Key 状态；Key 留空时保留已存凭据。读取失败会提示重试，不再当作未配置。设置页右上角有关闭按钮，返回侧聊时刷新配置状态。各安装副本仍有各自的存储，不能通过换目录自动迁移 Key。
- **小地图默认显示最近内容**：每次打开先滚到目录末尾，完整历史异步补齐时继续跟随末尾；用户主动向上浏览、点击定位或搜索后保持其位置。筛选控件固定在列表顶部。此操作只调整小地图列表，不主动将主对话跳到末尾。
- **取消侧聊引用**：引用框右上角的 × 只移除引用，保留问题草稿、已有侧聊和保存记录。生成中取消会中止本地请求并忽略迟到回复；不能追回已发送内容或保证服务商停止计费。
- **提示词保存**：明确区分可选名称和必填正文；正文输入框适配明暗主题、占满弹窗宽度。空正文有可见错误，保存失败保留输入，确认本地写入成功后才关闭弹窗。

本轮没有调用真实模型或执行真实聊天写入。API 配置跨设置页及后台实例恢复通过模拟存储验证，真实配置曾需重填的完整原因尚未确认。测试和证据边界见 [验证记录](docs/VALIDATION.md)，更新历史见 [CHANGELOG.md](CHANGELOG.md)。

## 安装

运行扩展不需要 npm、服务器或编译。

1. 下载源码 ZIP 并解压，或克隆仓库。
2. 在 Chrome 地址栏输入 `chrome://extensions/`，开启右上角「开发者模式」。
3. 点击「加载未打包的扩展程序」，选择**直接包含本文件和 `manifest.json` 的文件夹**。
4. 打开或刷新 `https://chatgpt.com/`，将扩展固定到工具栏便于进入设置。

已有 Chat Shelf 用户：候选目录会形成另一安装实例，Chrome 的扩展 ID 和本地存储可能不同。先保留原安装并备份，不要直接卸载，也不要在同一页面同时启用两份扩展。迁移说明见 [MIGRATION.md](MIGRATION.md)。

**已有安装更新到 0.3.2**：优先把运行文件更新到原先加载的同一目录，然后在 `chrome://extensions/` 点击该扩展的「重新加载」，核对版本，再刷新 ChatGPT 标签页。不要把每次更新解压到不同目录重新安装；不同扩展 ID 的资料与 API 配置不会共享。

## 使用入口与当前范围

| 功能 | 入口及行为 |
| --- | --- |
| 本地文件夹、星标、标题搜索 | 原生历史区内折叠的「本地文件夹与批量管理」；无法可靠定位原生历史区时，点扩展图标打开右侧管理。需要先连接当前账号。支持嵌套文件夹和拖拽分类。 |
| 多选与批量操作 | 本地管理内「多选」及批量操作栏。归档、取消归档和删除默认禁用，开启后仍需逐批确认，删除还需输入确认文字。首错即停，区分失败和结果不确定。 |
| 小地图 | 右侧「小地图」。默认列用户提问，可按标题、正文和代码筛选。读取当前对话的当前分支目录，点击卡片定位；读取或定位失败会提示。 |
| 侧栏聊天 | 右侧「侧栏聊天」，或选中主对话文字后「侧栏追问」。引用与侧聊上下文只在主动提问时发送到自己配置的 API，不自动发送主聊天。 |
| 书签、笔记 | 右侧对应按钮和消息下操作入口；支持当前对话/全部范围、本地保存和编辑。 |
| 导出 | 原生输入框上方右侧「导出⌄」，备用入口为扩展图标→导出当前对话。HTML、Markdown 可下载；PDF 先打开临时预览，再由用户打印另存。 |
| 提示词和草稿辅助 | 输入框上方提示词库与规则优化。规则优化不等同于 AI 优化；快捷追问只填写草稿。 |
| 备份与恢复 | 扩展图标→工具设置/本地备份，或本地管理内备份/恢复。按 ChatGPT 账号隔离，不含 API Key。 |

本地文件夹与 ChatGPT 原生 Project 是两回事：分类不修改服务器项目。小地图目录中的系统/工具/隐藏推理消息以及其他分支不会列入；附件仅作文字标记。完整目录读取使用 ChatGPT 未公开接口，可能失效，届时仅保留已识别页面内容并标注不完整，不能保证任何页面都能一键定位。

## 配置自己的 API

1. 点扩展图标→「云端 API 设置」，填写提供商给出的 HTTPS 基础地址、准确模型名和 API Key。
2. 点击「保存并授权此域名」，核对 Chrome 权限提示。保存配置不会发模型请求。
3. 返回侧栏聊天，选择云端 API，输入问题后点「提问」。支持流式输出和停止。

采用 Bearer Key + Chat Completions 兼容协议，也接受以 `/chat/completions` 结尾的完整地址。不支持额外签名认证或仅有 Responses 接口的服务。服务商的费用、限额和隐私规则独立适用；**扩展代码开源免费，不代表云端模型免费**。Chrome 本机 AI 是可选的手动模式，支持情况取决于浏览器和设备。

API Key 仅在扩展设置中填写，不要提交到仓库或 issue。它保存在扩展本地存储，不是系统加密保险箱；不进入聊天备份、诊断或导出。详见 [隐私说明](PRIVACY.md)。

## 开发与安全演示

需要支持 `node:test` 的 Node.js；当前测试依赖为 jsdom 26.x。安装扩展本身无需执行这些命令。

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run check
npm.cmd test
npm.cmd run audit:publication
```

可在扩展弹窗点击「查看离线模拟」。`demo/index.html?fixture=virtual` 使用 60 轮/120 条虚构消息、仅挂载 5 条 DOM，测试长对话导航；`?fixture=cloud` 返回明确标记的假模型回答，不需要 Key。`demo/integration.html` 用于虚构账号菜单和导出入口回归。演示页不是登录后的 ChatGPT，也不是生产环境验收。

本目录不含其他扩展安装文件、真实聊天截图、聊天备份或开发者的浏览器配置。运行时代码无额外 npm 依赖；测试依赖见 [第三方说明](THIRD_PARTY_NOTICES.md)。兼容用的部分内部标识仍叫 `chat-shelf` / `ChatShelf`，原因见迁移说明。
